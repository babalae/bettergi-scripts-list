# 模板素材清单

## 目录结构

```
Assets/RecognitionObject/
├── 寄物装置.png              ┐
├── 打开寄物装置.png           │
├── 料理1.png / 料理2.png      │
├── 材料1.png / 材料2.png      ├ 固定模板：与 src/constants.js 的 TEMPLATE_DEFS
├── 寄物装置容量已满.png        │   里 file 字段一一对应，换图同名覆盖、别改文件名
├── 确认存取.png               │
├── 确认.png                   │
├── 拆除返还.png               │
├── 退出寄物装置页面.png        ┘
├── 截图方法模板.png            ← 占位图（标准图库），分类目录缺图时自动拷过去
├── 数字/ 0.png ~ 9.png         ← 数量识别用（物品下方的数字）
└── 目标物品/                  ← 目标物品单独放，按分类分子目录；在设置下拉里选
    ├── 料理/ 美味的提瓦特煎蛋.png …
    └── 材料/ …
```

> **关于「设置项」**：面板里只有「循环次数」「目标物品」两项。下文提到的其余设置项都有默认值
> （写在 `src/constants.js` 或代码里），需要时往 `settings.json` 加一个同名键即可生效。

固定模板换图：**保持文件名不变直接覆盖**。要改文件名必须同步改 `TEMPLATE_DEFS`。

目标物品换图：把 PNG 丢进 `目标物品/料理/` 或 `目标物品/材料/`，然后在设置里的**下拉**选它即可，**不用改代码**（下拉内容由脚本按目录自动生成，加图后启动一次就会刷新）。

## 固定模板用途

| 文件名 | 作用 | 出现时机 |
| --- | --- | --- |
| `寄物装置.png` | 确认造物类型已切到「寄物装置」 | 按 T 进入造物模式后，循环按 3 切换类型时 |
| `打开寄物装置.png` | 靠近装置时的交互提示 | 按 W 前进靠近装置时 |
| `料理1.png` / `料理2.png` | 装置界面的「料理」分类页签（两张候选） | 按 F 打开装置界面后 |
| `材料1.png` / `材料2.png` | 「材料」分类页签（两张候选） | 同上，分类设为「材料」时才用 |
| `寄物装置容量已满.png` | 容量满的提示 | 连点到上限时 |
| `确认存取.png` | 容量满后的「确认存取」按钮 | 出现容量已满提示后 |
| `确认.png` | 二次确认弹窗的「确认」按钮 | 点完确认存取后 |
| `拆除返还.png` | 拆除确认提示；出现它才说明当前能拆造物 | 按 T 切到删除之后；**也是开造前清场的判断依据之一** |
| `退出寄物装置页面.png` | 关闭装置界面的按钮 | 存取完成后 |

分类页签**不再由设置项选**：目标物品图放在 `目标物品/料理/` 就点料理页签，放在 `材料/` 就点材料页签；
没用到的那两张不加载也不校验。

## 开造前清场用的两张图

`打开寄物装置.png` 和 `拆除返还.png` 除了各自主流程的用途外，还承担**开造前清场**的判断：

| 屏幕上有 | 说明当前状态 | 清场动作 |
| --- | --- | --- |
| `拆除返还.png` | 已经在造物模式的**拆除确认态** | 不用按键，直接左键拆除 |
| `打开寄物装置.png` | **普通状态**，人就站在装置旁边 | T 进造物 → T 切删除 → 校验拆除返还 → 左键拆除 |
| 都没有 | 场地干净 | 什么都不做，直接进造物 |

因为造物同时只能存在一个，场上有旧的时新的是放不下去的，所以这一步放在**视角调整之后、按 T 之前**——视角固定后才能可靠识别。

拆完会再查一轮，直到干净或达到 `clearExistingMax`（默认 3）。
`拆除返还.png` 若连续 2 次仍在（界面没关透或误匹配），会收手并打 warn，不会一直拿鼠标戳画面中心。

设置项 `clearExistingEnabled` 可整体关掉这一步。

## 怎么截这些图

**BetterGI 本身没有"模板截取"按钮**，GUI 上没这个入口。实际做法就是普通截图 + 裁剪：

1. 游戏调到 1920×1080 窗口化（16:9），关掉 HDR / 显卡滤镜，亮度保持默认；
2. 把画面停在模板会出现的那一刻（比如装置界面打开、容量已满提示弹出）；
3. 用任意截图工具框选目标区域 —— `Win + Shift + S`、微信、QQ、ShareX 都行。ShareX 会直接显示选区的像素宽高，比较方便；
4. 存成 **PNG**，**不要缩放、不要用 JPEG**；
5. 按上面的目录结构放进去。

## 三条经验

1. **不要截进会变的东西** —— 数量角标、选中态高亮、相邻列表条目、鼠标光标。这些一变，模板就废。
2. **背景占比别太大** —— 模板匹配用的是归一化相关系数，整张模板含背景一起比。背景在游戏里如果对不上，会拉低总分，只能靠调低阈值补救（阈值越低越容易误匹配）。更有效的做法是配 `roi` 限定搜索区域。
3. **尺寸必须 1:1** —— 模板匹配不做缩放。游戏里图标多大，模板就得多大。

## 目标物品单独说明：阈值别调太低

目标物品默认 **阈值 0.85**（其余模板 0.7），并且默认开**彩色（三通道）匹配**。原因值得记住：

> **「奇怪的XXX」其实就是「美味的XXX」整体压暗一档。**
> 模板匹配默认用灰度 + TM_CCOEFF_NORMED，这个算法会先做**去均值**再归一化，
> 也就是说**整体变暗对它几乎没影响** —— 灰度下「奇怪的」和「美味的」长得几乎一样。
> 阈值一旦放低（比如 0.6），就会把奇怪的当成美味的存进去。

两道保险：

1. **阈值抬高到 0.85**（设置项 `targetFoodThreshold`，百分数）；
2. **开彩色匹配**（设置项 `targetFoodUse3Channels`，默认开）—— 压暗不只是亮度变了，色相/饱和度也会变，彩色三通道能把这些差异算进去。

查找范围默认限制在**屏幕右半边**（`roi: { x: 0.5, y: 0, w: 0.5, h: 1 }`），避免在左侧列表里误点。设置项 `targetFoodRightHalfOnly` 可关掉。

### 排错顺序

匹配不上时**不要第一反应就调低阈值**，按这个顺序来：

1. 确认游戏分辨率和截图时一致（1920×1080 窗口化），确认开的是彩色匹配；
2. 确认截图是**目标品质那一张**（要存美味的就截美味的，别拿奇怪的图去存）；
3. 重截一张 —— 多半是尺寸或样式对不上；
4. 最后才动 `targetFoodThreshold`，而且**别低于 70**；低于 70 就容易把奇怪的混进来。

想主动区分品质的话，可以把「奇怪的XXX」也截一张放旁边备用，需要时把文件名填进设置里当对照。
