# AAA愚人众寄物装置·存完就寄

BetterGI JS 脚本。自动完成「放置寄物装置 → 存入指定物品 → 寄出 → 拆除装置」，支持多轮。

---

## 一、这个脚本做什么

至冬的「愚人众寄物装置」可寄存背包物品再寄出。手工流程为：
进造物模式 → 选类型 → 放置 → 走近 → 打开 → 翻页找物品 → 逐个点入 → 确认 → 退出 → 拆除。

本脚本全自动执行该流程：

```
传送至七天神像（恢复 60% 热能）
   ↓
放置寄物装置 → 走近并打开
   ↓
切到对应分类 → 列表中找到目标物品 → 识别剩余数量 → 连点存入
   ↓
确认存取 → 确认 → 退出装置页面
   ↓
拆除装置
```

要存哪个物品在设置下拉中选；一次运行可跑多轮。

- 每步均以模板匹配确认状态，未命中则报错停止，不做无校验点击；
- 前置检查（素材完整性、是否选中占位项）在**传送之前**完成，不合格时不操作游戏；
- 出错信息与《诊断报告》写入脚本目录 `debug/日期_时段.txt`。

## 二、使用方法

### ① 截图

打开背包或寄物装置界面，截取**要存入的物品条目**：

- 存为 **PNG**，不缩放、不用 JPEG；
- 分辨率与运行时一致（16:9，建议 1920×1080 窗口化）；
- 关闭 HDR 与显卡滤镜，游戏亮度保持默认；
- **只截条目本体**（图标 + 名称）。数量角标、选中高亮、相邻条目都会变化，截进去会导致模板失配。

### ② 放入对应目录

```
Assets/RecognitionObject/目标物品/
├── 料理/    ← 料理类截图
├── 材料/    ← 材料类截图
└── 不执行/  ← 备用图（脚本不扫描此目录）
```

- 文件名任意，脚本按目录下实际文件识别；
- 图片所在子目录即分类，无需单独选择；
- 目录内的 `截图方法模板.png` 是占位图，不计入候选。

### ③ 添加脚本

将脚本目录放入 BetterGI 的 `User/JsScript/`，在脚本组中添加（或订阅 / 导入）。

### ④ 配置

右键脚本 → **修改 JS 自定义配置**。必填一项：`目标物品` 下拉。

> 首项「刷新当前图库」表示未选择，选中后脚本提示并停止（防误存）。它是占位项，不是按钮。
> 刷新图库 = 放入截图 → 重启脚本（见 ⑤）。

### ⑤ 首次运行

首次运行（或增删过截图）时，脚本扫描目录并比对下拉选项；有增减则改写 `settings.json` 后停止，日志输出「已完成刷新」。

BGI 无手动刷新入口——重启脚本即刷新。**再启动一次**，下拉即为新名单。

### ⑥ 选好后启动

在下拉中选中目标物品，再启动一次即正式运行。首次建议 `循环次数` 设为 1。

### 更新脚本时，什么是保得住的

BGI 更新脚本的做法是**把整个脚本目录删掉再重新拷贝**。所以 `manifest.json` 里声明了
`saved_files`，这两个路径会先备份、更新完再还原：

- `Assets/RecognitionObject/目标物品/` —— 你的图库（`料理/` `材料/` `不执行/`）
- `debug/` —— 历史排障日志

也就是说：**你自己丢进 `目标物品/` 的截图，不会被更新冲掉。**

两点要知道：

- `settings.json` **不在**保护名单里。它每次更新都会回到出厂状态（下拉只剩占位项），
  于是下次启动时脚本会检测到差异、自动重建下拉并停下 —— **再启动一次即可**，
  和首次安装的流程一样。你的"选了哪个物品"存在 BGI 的配置组里，不受影响。
- 反过来，**受保护目录里由脚本自带的文件会被冻结**（还原是覆盖式的）：比如
  `目标物品/{料理,材料}/截图方法模板.png`，以后更新也改不动它。它只是占位图，无妨。

## 四、运行环境

- BetterGI `0.64.0` 或更高；
- 简体中文客户端，16:9 画面，建议 `1920×1080`；
- 截图方式 `BitBlt`，保持默认亮度，关闭 HDR 与显卡滤镜；
- 水平 / 垂直镜头灵敏度均为默认值 `3`（镜头标定依赖它）；
- 运行期间不要操作键鼠。

## 五、排查

表内提到的常量均在 `src/constants.js`。

| 现象 | 先查这里 |
| --- | --- |
| 提示缺少模板 | `Assets/RecognitionObject/` 下文件名是否与 `TEMPLATE_DEFS` 一致；日志会打完整路径 |
| 「目标物品目录下没有可识别的 PNG」 | `Assets/RecognitionObject/目标物品/{分类}/` 下没有 `.png`；放一张要存入的物品截图即可 |
| **日志打「已完成刷新」然后停了** | 正常机制：目录内容与下拉有增减，脚本已改写 `settings.json`。**再启动一次**即可 |
| **日志打「未选择目标物品」** | 下拉还停在第一项「刷新当前图库」。去设置里选一个真实物品 |
| 下拉里看不到刚加的图 | 先确认图放在 `目标物品/料理/` 或 `材料/`（不是 `不执行/`）；刷新后**再启动一次**才会显示 |
| 分类目录缺「截图方法模板.png」 | 脚本会自动从 `Assets/RecognitionObject/截图方法模板.png` 拷一份；失败会提示，手动复制即可 |
| **数量识别结果不对 / 认不出数字** | 《诊断报告》**每轮都写进 `debug/日期_时段.txt`**（恒开，无需开关），日志用 `[征收须知]` 报落点。照③挑最准的系数、照②挑偏移，在 `settings.json` 里加 `digitScale`（百分数，缺省 100 = 1.00）与 `countRegionOffsetY`（像素）两项即可覆盖 |
| 点击次数明显少于实际数量 | 同上，数量认小了；日志会打「清点战利品：N 个」 |
| 认出的数量比实际多一位（1667 → 11667） | 区域框进了图标左边缘的竖线。已修（`countRegionPadX` 默认 0 + `digitHeightTol`）；若你的截图不同，把 `countRegionPadX` 调成负数往里缩 |
| 真实数量被判成误识别（如材料 9995 被丢掉） | 上限按分类取，材料 9999 / 料理 2000。料理认到 9995 才是真误识别 |
| 存进去的是「奇怪的XX」不是「美味的XX」 | 阈值别低于 70；确认开了彩色匹配；确认截图截的是美味的那张 |
| 存进去的不是目标物品（混进了别的东西） | 数量没认准 → 点击上限退回容量 32 → 会误存。先按《诊断报告》把数量认准，别硬跑 |
| **只点 1 次就停，提示「第 1/32 次后…清掉选中态仍认不到目标」** | 不是存完了。要么目标被选中态改了样（页签没清掉）、要么它**挪出了锁定半径 60px 且全屏认到 0 个或 ≥2 个**（列表滚走了/出现两个长得像的）。按《诊断报告》核一遍阈值与候选 |
| **报错「翻到底了，这排货架里没有它」** | 列表连续 3 次翻页画面没变化，判为拉不动了。**先想最常见的一种：上一轮是不是已经把它全存进装置了**——存完背包里就没有了，这一栏自然翻不到。确认目标图确实在这一分类下（不是放错了子目录）；**若列表明明还能往下滚却误报**，说明取样区域没盖住列表 → 把 `scrollProbeRegion` 的 `x/y/w/h` 往列表那一列挪，或把 `scrollProbeChangedPct` 调小（翻页动画细微时）、`scrollBottomHits` 调大更保险 |
| **列表明明到底了却还是滚满 50 次** | 两条比对路子都没取到值（当前环境不支持逐像素取值、模板匹配也没跑起来）→ 保守当"变了"继续滚。去看 `debug/日期_时段.txt` 里有没有 `[Probe]` 开头那几行（每次翻页一行，会写明"变化 X%"和走的哪条路子） |
| **报错「连着 3 次位置都在变」** | 列表一直在动（滚动惯性没停 / UI 每点一次就重排）。先把 `scrollSettleDelay` 调大；真不行就把 `foodUnstableStop` 调大让它多验几次 |
| **「确认」「退出」点了没反应** | 调大 `src/constants.js` 的 `afterConfirmAccessDelay` / `afterConfirmDelay` |
| 点击落空或点错 | 确认 `placeAtCenterFirst` 为 `true`；给模板加 `roi` |
| 传送后后续步骤全偏 | 调大 `restoreDelay`（如 3000），等加载完成 |
| **想看排障日志但 `debug/` 里没有这一趟的文件** | 正常：这一趟**一个字都没记上**（典型是"启动检查没过就直接停"）→ 不写盘也不提示落点。真跑起来一定会有 |
| 想看排障日志在哪 | 脚本目录下 `debug/YYYY-MM-DD_HHMM.txt`。写不进去（权限等）会退回脚本根目录，日志末尾会写明实际落点 |

## 六、已知限制

- BetterGI JS 环境无原生滚轮 API。滚动由 `keyMouseScript.run()` 注入宏事件；
  不支持时回退到 `Assets/KeyMouse/滚轮下翻.json`（一次固定 120 单位，日志会说明）。
- 模板匹配**不做缩放**，模板尺寸必须与游戏内实际显示尺寸一致。
- 删除与存取结果不做二次校验，仅以按钮模板是否命中为准。
- 循环中途报错时兜底收尾：装置**已落地**则走「退页面 → 拆装置」；未落地则只退造物界面。
  拆除失败会提示「现场可能留有残留造物，请手动拆除」。
