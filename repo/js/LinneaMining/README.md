# 莉奈娅挖矿一条龙

专用于运行莉奈娅自瞄挖矿的脚本，不分矿种，只挖稳定刷新的矿物。  
自带月卡监听，可跨4点执行，但月卡跳出时脚本仍在执行，可能会引起故障。  
本脚本不会提供过多设置项，仅保留必要设置，最大程度限制设置数量。

## 多账号

矿点刷新是按账号独立计算的，两个账号混用一份进度会互相误判「已挖过」。脚本默认按当前登录账号隔离：

- 启动时 OCR 读取游戏右下角 UID，进度写入 `local/refresh_records_<UID>.json`
- 第一次启用时，旧的 `local/refresh_records.json` 会整体迁移给首个识别到的账号，并打上一次性迁移标记；之后再新建账号一律从空记录开始，不会继承别人的进度
- UID 识别失败（游戏里隐藏了 UID，或 OCR 没认出来）时，进度落到 `refresh_records_unknown.json`。这时在「账号标识」里手动填「大号 / 小号」最稳，优先级高于 OCR
- 关掉「多账号独立刷新记录」就回到单份全局记录，和旧版行为一致

账号切换本身由 BetterGI 的配置单 / 启动器完成（脚本没法重启游戏换号），切完号重新运行脚本即可。日志第一行会打印 `当前账号：xxxx（UID 自动识别）`，方便确认这次跑的是哪一份记录。

## 路线来源

蒙德至至冬的 247 条路线移植自 [矿产资源批发（AbundantOre）](https://bgi.sh/?type=js&path=AbundantOre) 的真实录制路线，按该脚本的莉奈娅适配算法转换：

- 相邻矿点距离小于 7.5 米时合并，只保留一个射击点，避免对同一矿堆重复蓄力
- 沿来路方向把矿点坐标外推 0.75 米（远古圣山 2.0 米），给射击留出站位
- 删除矿点后紧跟的无效路径点（10 米内的空路径、纯等待、绕圈拾取）
- 矿点动作统一替换为 `莉奈娅 w(0.05),wait(0.15),moveby(0,2500),wait(0.15),charge(0.65),click(middle)`
- 原作者重新录制过的 29 条覆盖版优先使用，仅把其中残留的 `mining` 动作补换成莉奈娅射击

纳塔 27 条、挪德卡莱 29 条是你原有的自录路线，未做改动。

## 7.2 新区域为什么是空的

原神 7.2「坏灭肇始之时」（2026-11-04）开放的至冬东部（新基捷城、如翼之峰等）目前在本地任何素材里都没有矿点录制数据。矿点坐标必须来自游戏内实际走位，凭空生成会直接把角色带进墙里或原地打转，所以这部分需要实机录制一遍，再用 `tools/record_to_linnea.py` 一键转成本脚本格式。

录制方法：

1. BetterGI → 路径记录，进入至冬新区域，沿矿点走位，每个矿堆按一次「记录挖矿点」
2. 保存后得到 pathing JSON
3. 运行：

```powershell
python tools\record_to_linnea.py --region 至冬 --ore 虹滴晶
```

脚本会自动把录制文件里的 `mining` 点换成莉奈娅射击，加上矿种 tag，写进 `paths\至冬\`。

## 运行时长的现实预期

路线一共 303 条，按 AbundantOre 的实测均值约 90 秒/条，全跑一遍在 6～8 小时量级。日常不建议全选：

- **按地区跑**：在「跳过以下地区」里勾掉不想跑的国家，只留当前需要的
- **按时长跑**：在「目标运行时长（分钟）」填 60 / 120，到点自动停

## 说明

说在最开始：莉奈娅挖矿需要识别元素视野下的黄色岩元素属性矿物，原神设置项开的过低会导致黄色变浅，识别率下降，在足够运行的情况下请不要为了节省微乎其微的耗能将设置调的过低

其它：
- 队伍中必须包含**莉奈娅**，不建议在**挪德卡莱**地区携带**哥伦比娅**，部分矿点的犀牛会影响挖矿。
- 请配置好自动战斗策略，建议关闭战斗后的自动拾取，战斗点位仅为必经之路或高收益处。
- 若观察到部分点位射一箭无法满足挖掘全部，请反馈给我（如果漏的是铁矿不会考虑，被小动物挡住也大概率不会修改）
- 有一部分铁矿点位位置较为刁钻，加之铁矿这种矿物本身较无用，将不会收录在本脚本的路线内，同理，其它个别位置刁钻的矿物点位也不会专程前往。
- 移植路线保留了原录制中的战斗点（tag 带「战斗」），可在设置里勾选「跳过战斗点位」排除。
