# 采集 CD 管理

## 一、功能与运行前提

本脚本用于在 BetterGI 中编排和执行采集路线，并按账户维护路线冷却时间、拾取历史和材料目标。当前版本以“任务编排 + 路径组”为核心：任务决定路线范围、运行优先级和退出条件，路径组只保存对应文件夹的 CD、队伍和游戏时间设置。

- 需要 BetterGI `0.62.0` 或更高版本。
- 通过 BetterGI 配置组运行，`settings.json` 只提供“启动时打开 HTML 配置面板”开关。
- 业务配置保存在当前 BetterGI 配置组的 `settings` 对象中，不保存在 `settings.json`。
- HTML 页面只负责展示和收集配置；文件读取、数据校验、配置保存及脚本执行均由 `main.js` 完成。
- 路线文件需要放在脚本目录的 `pathing/一级文件夹/` 中。一个一级文件夹只能配置给一个路径组。
- 路线能否正常执行仍取决于 BetterGI 版本、路线内容、队伍、游戏画面和网络状态。

## 二、快速上手

### 1. 准备路线

推荐运行脚本随附的 `pathing/采集cd管理路线工具.exe` 建立和更新映射；工具的独立说明位于 `pathing/README.md`。初始 `pathing` 不包含路线，只有这两个工具文件。也可以从 BetterGI 已订阅的地图追踪中手工复制需要的路线，按用途放入本脚本的 `pathing` 一级子文件夹。例如：

```text
采集cd管理/
└─ pathing/
   ├─ 区域特产/
   │  ├─ 蒲公英籽01.json
   │  └─ 绯樱绣球01.json
   └─ 矿物/
      └─ 水晶矿01.json
```

建议保证路线文件名唯一。运行记录以文件名匹配，同名路线会共用或冲突同一条 CD 与历史记录。

### 2. 打开配置面板

1. 将脚本加入 BetterGI 配置组。
2. 右键打开自定义配置，确认“启动时打开 HTML 配置面板”已勾选；新配置默认勾选。
3. 运行脚本，在 HTML 面板中完成配置。
4. 点击“保存并继续”，脚本保存配置后开始执行。

入口开关保持由 BetterGI 自定义配置控制：勾选时每次启动都会打开面板；不需要打开时，应在自定义配置中取消勾选，脚本随后会直接使用上次保存的业务配置。点击“取消”或直接关闭面板会放弃本次修改并终止本次脚本运行。

面板初始化完成后会检测用户活动。连续 60 秒没有鼠标、键盘、输入、选择或滚动操作时，弹窗提示将在 10 秒后自动保存当前配置并继续运行；倒计时期间进行任意操作会取消本次自动保存，并重新开始 60 秒计时。自动保存复用手动保存的校验流程，保存失败时会保留面板和错误信息，等待用户处理。

### 3. 最小可运行配置

1. 在“基础设置”页填写账户名称，按需设置默认队伍和拾取模式。
2. 在“路径组”页新增路径组，选择一个 `pathing` 一级文件夹，并设置 CD 类型。
3. 在“任务编排”页新增任务，选择允许使用的路径组。
4. 保持任务启用，按需填写目标、禁止时间、时长、排序和最低效率。
5. 保存并继续。

只想依次执行当前可用路线时，可以不填写每日目标和一次性目标。未配置任何退出条件时，任务会一直参与调度，直至没有可用路线。

## 三、核心概念

### 1. 任务编排

任务是调度单位。右侧任务列表从上到下表示优先级，可拖动调整顺序；左侧编辑当前任务。

每个任务可以独立配置：

- 是否启用。
- 允许使用的路径组。
- 是否允许再次开启。
- 是否仅执行目标材料相关路线。
- 每日目标和一次性目标。
- 任务级禁止运行时间。
- 单次运行总时长。
- 路线排序方式。
- 最低效率。

任务名称只是显示名称，内部使用创建时生成的 ID 保存配置。修改路径组名称后，任务中的路径组显示会同步变化；删除路径组后，该路径组会从非“全选”任务的允许列表中移除。

### 2. 路径组

路径组只描述 `pathing` 某个一级文件夹的执行参数，不决定运行顺序，也不直接保存采集目标。

每个路径组包含：

- 显示名称。
- 对应的一级文件夹。
- CD 类型。
- 默认队伍。
- 自动调节游戏时间方式。

任务可以选择一个或多个路径组，也可以显式选择“全选”。“全选”保存为 `*`，会自动包含之后新增且已启用的路径组。

### 3. 调度循环

运行时采用以下循环：

1. 从任务列表第一项开始，跳过停用任务和本次运行中已被禁用的任务。
2. 检查任务退出条件。
3. 合并该任务允许路径组中的全部路线。
4. 依次应用失败路线、黑名单、禁用关键词、相关材料、CD 和最低效率过滤。
5. 按任务的 `sortMode` 对合并后的路线统一排序，执行第一条路线。
6. 一条路线结束后，重新从任务列表第一项开始检查。
7. 完整一轮没有任何任务执行路线时，脚本结束。

因此，高优先级任务每执行完一条路线都会重新获得检查机会。`allowReopen=true` 只表示后续轮次仍会检查该任务，不表示在整轮均无路线可执行时继续空转等待 CD。

每条路线开始前会输出 `INFO` 级当前进度。有每日目标时显示各材料的“已采集/目标数量”，有一次性目标时显示当前剩余量；没有明确目标时显示任务路线总数和其中处于 CD 的数量。日志中的任务累计执行时长与时长退出条件一致，只累计该任务实际执行路线及其准备、收尾工作的时间，其他任务运行期间不会继续计时。

运行期间会在游戏主界面左下方显示进度面板，实时展示当前任务、路线、目标进度和任务累计执行时长。面板每 200 毫秒复用主界面模板进行判断并刷新拾取进度；离开主界面后自动隐藏，返回主界面后恢复显示，且始终保持点击穿透。

### 4. 退出条件与目标

任务支持以下退出条件：

- 进入任务级禁止运行时间。
- 每日目标完成。
- 一次性目标完成。
- 达到该任务的单次运行总时长。
- 没有可用路线。

多个退出条件之间采用“或”：任意一项满足，当前轮次即不再运行该任务。单个每日目标或一次性目标中的多种材料采用“且”：所有材料均达到数量后，目标才算完成。

任务达到退出状态时会发送“`xxx任务已完成，退出条件：xxx`”通知；同一任务在单次脚本运行中至多发送一次，即使允许再次开启并在后续轮次再次退出也不会重复通知。

目标格式为 `材料*数量`，多种材料使用 `+` 连接：

```text
甜甜花*20+薄荷*10
```

- 每日目标按 UTC+8 凌晨 4 点划分统计日。
- 所有任务拾取到的材料都会参与每日计数，也都会扣减所有任务的一次性目标。
- 每日目标只计算当天已保存的拾取数量，不会改写原目标文本。
- 一次性目标会随拾取逐步扣减；全部完成后保存为 `已完成`，后续始终视为该退出条件已满足。
- 开启“仅执行相关路线”时，只保留与当前未完成目标材料相关的路线，已经完成的材料不再参与筛选。
- 每日目标和一次性目标都为空时，即使开启“仅执行相关路线”也不会筛选路线。

关闭“允许再次开启”后，任务一旦因退出条件或无可用路线退出，就会在本次脚本运行中被禁用。开启时任务会在后续调度轮次继续接受检查。

“无可用路线”可能表示允许路径组为空、路径组未启用、路线执行失败、路线被排除、没有相关路线、全部处于 CD 或全部低于效率阈值。

## 四、HTML 配置面板

### 1. 基础设置

#### 通用设置

| 配置项 | 默认值 | 说明 |
|---|---:|---|
| 账户名称 | `默认账户` | 用于区分 `record/<账户>/` 和 `blacklists/<账户>.json`。切换账户时，面板会重新加载对应的黑名单和信息数据。 |
| 默认队伍 | 空 | 路径组没有填写队伍时使用；路径组队伍优先。名称需要与 BetterGI 中的队伍名称一致。 |
| 索引处理方式 | 执行任务 | 普通模式会在索引不存在时创建；强制刷新会重置当前路线 CD，并在索引成功写回后自动恢复普通模式。 |
| 材料价值倍数 | 空 | 格式为 `材料*倍数`，多个条目使用中英文逗号分隔；未配置材料按 `1` 计算。支持材料名称拼音补全。 |

“重新生成索引文件（用于强制刷新CD）”会把当前路线的 CD 重置到初始时间，同时保留历史记录和已失效的旧记录。索引成功写回后，脚本会自动把该配置恢复为“执行任务（若不存在索引文件则自动创建）”；写入失败时保留强制刷新模式，供下次运行重试。

#### 拾取设置

| 配置项 | 默认值 | 说明 |
|---|---:|---|
| 拾取模式 | 模板匹配拾取 | 可选“模板匹配拾取”或“bgi原版拾取”。 |
| 识别间隔 | `100` 毫秒 | 仅模板匹配拾取生效，可填写 `16` 至 `200`。 |
| 黑名单 | 空 | 用中文分号分隔；启动时以当前账户本地文件为准，面板用于人工编辑和同步保存。 |
| 禁用名称关键词 | 空 | 仅用于路线排除，不影响拾取，也不会把对应材料的效率权重改为零。 |
| 禁用拾取二次校验 | 关闭 | 仅模板匹配拾取生效。禁用校验可能改变误识别和漏识别情况。 |
| 跳过路线终点坐标校验 | 关闭 | 仅在 BetterGI 没有返回布尔型路线结果、脚本回退到终点坐标校验时生效。 |

材料名称输入栏支持拼音匹配。输入部分名称或拼音后，可点击候选项，或按 `Tab` 选择首个候选项。

### 2. 任务编排

| 配置项 | 新任务默认值 | 实际行为 |
|---|---:|---|
| 名称 | `新任务` | 仅用于显示，可重复但不建议重复。 |
| 状态 | 启用 | 停用后整个任务不参与调度。 |
| 允许再次开启 | 开启 | 关闭后，满足退出条件或无可用路线时，本次脚本运行内禁用任务。 |
| 仅执行相关路线 | 开启 | 存在未完成目标时，只筛选与这些材料相关的路线。 |
| 允许路径组 | 全选 | 可显式全选或选择多个路径组；不选择时没有可运行路线。 |
| 路线排序 | 文件顺序 | 对任务允许路径组中的合并路线统一排序。 |
| 最低效率 | `0` | 单位为加权拾取数/分钟，低于此值的路线被过滤。 |
| 每日目标 | 空 | 多材料全部满足后退出；每日 04:00 重置统计日。 |
| 一次性目标 | 空 | 逐次扣减，全部完成后保存为 `已完成`。 |
| 任务级禁止运行时间 | 空 | 命中任一时间范围时跳过任务。 |
| 单次运行总时长 | `0` 分钟 | 累计该任务实际执行路线及其准备、收尾工作的时间；其他任务执行期间暂停计时，`0` 表示不限时。 |

路线排序方式：

- `文件顺序，按在文件夹中位置顺序运行`：保留读取路线后的文件顺序。
- `优先最早刷新，将优先执行最早刷新的路线`：只在已经到 CD 的候选路线之间，按记录中的历史 CD 时间升序。
- `优先最高效率，将优先执行最高分均拾取物的路线`：按当前任务计算出的效率降序。

时间规则支持中英文逗号、冒号和跨日范围：

```text
8，23:11，08:00-11:30，23:00-04:00
```

- 单独的 `HH` 表示完整一小时，例如 `8` 表示 `08:00–08:59`。
- 单独的 `HH:mm` 表示该一分钟，例如 `23:11` 在 `23:11` 这一分钟内生效。
- 时间范围包含开始和结束分钟，例如 `08:00-11:00` 包含 `11:00`。
- 结束时间早于开始时间时按跨日范围处理，例如 `23:00-04:00`。

### 3. 路径组

| 配置项 | 新路径组默认值 | 实际行为 |
|---|---:|---|
| 名称 | `新路径组` | 任务中显示该名称；改名不会改变内部 ID。 |
| 文件夹 | 未选择 | 只能选择 `pathing` 下的一级文件夹；同一文件夹不能属于多个路径组。 |
| CD 类型 | `1次0点刷新` | 空值在界面中显示为“不启用”，该路径组不会参与任务。 |
| 默认队伍 | 空 | 为空时回退到基础设置中的默认队伍。 |
| 自动调节游戏时间 | 不调节时间 | 可选不调节、尽量调为白天或尽量调为夜晚。 |

固定 CD 类型的含义：

| CD 类型 | 下一次可用时间 |
|---|---|
| `1次0点刷新` | 下一自然日 00:00 |
| `2次0点刷新` | 第二个自然日 00:00 |
| `3次0点刷新` | 第三个自然日 00:00 |
| `4点刷新` | 下一个 04:00 |
| `12小时刷新` | 路线开始时间后 12 小时 |
| `24小时刷新` | 路线开始时间后 24 小时 |
| `46小时刷新` | 路线开始时间后 46 小时 |
| `每天一次` | 04:00–15:59 开始执行时记到次日 04:00；16:00–03:59 开始执行时记到 12 小时后 |
| `不指定` | 根据本次拾取到的材料自动计算，见“CD 与效率计算” |
| 空值 / 不启用 | 路径组不参与任务 |

自动调节游戏时间按路径组生效。相同模式通常最多约每 10 分钟调节一次；白天与夜晚模式发生变化时会立即切换。

### 4. 食材加工

食材加工是全局配置，可选择面粉、兽肉、鱼肉、糖、奶酪等加工项，并设置识别间隔。识别间隔必须为正数，默认 `50` 毫秒。

- 食材加工在准备执行路线时触发。
- 第一条路线前会检查一次，之后约每 95 分钟再次检查。
- 如果本次没有任何路线执行，不会单独进入食材加工。

### 5. 信息展示

信息展示页为只读视图，使用打开面板时已经保存到文件和 `settings` 的数据。面板中尚未保存的修改不会即时参与统计或预览计算。

#### 拾取历史

- 折线图展示最近最多 30 个统计日的拾取总量，日期以 UTC+8 凌晨 4 点为分界。
- 筛选框留空时统计全部材料；输入多个材料时，折线图汇总这些材料的数量。
- 筛选只影响折线图，下面的汇总表仍显示全部材料统计。

#### 路线浏览

- 按类似文件资源管理器的树形结构浏览路线，也可按名称或路径搜索。
- 可查看 CD、当前是否到期、效率、路径组、关联任务、地图、点位、作者、标签、路线声明和最近历史。
- “可运行 / CD 中”只表示 CD 是否到期，不包含黑名单、禁用关键词、目标相关性或效率阈值过滤。
- 关联任务列表可能包含已经停用的任务。

#### 任务预览

- 展示任务配置、允许路径组、路线数量、CD 已就绪数量和目标剩余量。
- 这是调度前的静态预览，不是脚本运行过程中的实时状态。
- “CD 已就绪”主要按允许路径组和 CD 统计，不代表路线经过全部过滤后一定可执行。

#### 数据诊断

展示路线文件、路线记录、失效旧记录、重名路线、历史条目、拾取记录天数、材料种类、黑名单、任务和路径组数量。失效旧记录表示索引中仍有记录，但当前 `pathing` 中已找不到同名文件；信息页不会自动删除这些记录。

## 五、CD 与效率计算

### 1. 固定 CD 与自动 CD

路径组选择固定 CD 类型时，该类型直接决定路线的下一次可用时间，会覆盖路线执行过程中按材料推算的 CD。

选择 `不指定` 时：

1. 如果本次拾取命中当前任务的未完成目标材料，只使用命中的相关材料计算。
2. 如果没有命中目标材料，使用本次全部拾取材料计算。
3. 多种材料分别计算 CD，取最晚的时间。
4. 没有识别到材料，或材料不存在于 CD 映射表时，按 `1次0点刷新` 处理。

Schedule 路线和短于 10 秒、不会写入有效历史的路线也会按路径组规则设置 CD，避免在同一次调度中立即重复执行。

### 2. 材料 CD 表

材料名称与 CD 类型保存在：

```text
assets/materialCdMap.json
```

需要添加新材料时，在对应分类对象中加入 `"材料名称": "CD类型"`。当前程序读取 `46h特产`、`12h素材`、`4点刷新` 和 `0点刷新` 四个对象，值应使用脚本支持的 CD 类型名称。

材料模板与 CD 表相互独立：CD 表负责刷新时间，`assets/targetItems/` 下的 PNG 模板负责模板识别、名称补全和别名关系。

`assets/materialCdMap.json` 是随脚本分发的资源，没有列入 `saved_files`。自行修改后应另行备份，脚本更新可能用仓库版本覆盖该文件。

### 3. 路线效率

效率单位为“加权拾取数/分钟”。材料价值按以下规则计算：

- 未配置倍数的材料权重为 `1`。
- 配置 `甜甜花*2` 后，每个甜甜花按 `2` 计入效率。
- 黑名单材料权重固定为 `0`。
- 开启“仅执行相关路线”且存在未完成目标时，只计算未完成目标材料的效率。
- 未启用相关路线筛选时，计算路线中的全部材料。
- 有至少 3 条有效历史时，使用最近历史的平均效率。
- 历史不足 3 条时，可以使用路线描述中的声明材料和声明用时。
- 无法得到已知效率时，使用默认分位效率，并保证不低于当前任务的最低效率。

最低效率应用在排序之前。任务允许多个路径组时，全部路线先合并，再以同一套任务级效率规则过滤和排序。

### 4. 路线声明

推荐在路线 `info.description` 中使用以下格式：

```text
【用时60秒，甜甜花*12，枫木*5】
```

同时兼容旧数量格式：

```text
2个薄荷；3个日落果；
```

声明数量会覆盖历史或实际识别中的同名及别名材料，避免重复计数。`【材料*数量】` 声明本身不作为普通描述参与黑名单文本排除；路线中的其他描述仍会参与。

## 六、拾取、黑名单与材料模板

### 1. 模板匹配拾取

模板匹配模式由脚本识别交互列表并执行拾取。

- 模板来自 `assets/targetItems/` 及其子目录中的 `.png` 文件。
- 模板文件名作为材料或交互名称。
- 路径中的 `[名称]` 会建立别名关系，例如目录 `[鳗肉]` 下的模板可归并到鳗肉。
- 支持拾取二次校验和背包满检测。
- 识别到某材料背包已满时，会把该材料加入当前账户黑名单。

### 2. BGI 原版拾取

该模式使用 BetterGI 的 `AutoPick` 实时触发器。原版拾取器会自行输出拾取日志，脚本只回收记录，不重复输出“交互或拾取 xxx”。脚本仍会扫描背包满提示并将识别到的材料加入黑名单，用于后续路线排除，但不会执行模板匹配拾取或 `F` 交互。

脚本通过 `dispatcher.getPickRecords()` 获取拾取结果，用于：

- 路线 CD 自动计算。
- 路线历史效率。
- 每日拾取统计。
- 一次性目标扣减。

如果当前 BetterGI 没有提供 `getPickRecords()`，原版拾取仍可能正常工作，但本脚本无法统计这些拾取结果。脚本账户黑名单不会控制 BetterGI 原版拾取器本身，但仍会用于路线排除和效率扣减。

### 3. 黑名单与禁用名称关键词

启动时黑名单优先从以下本地文件读取：

```text
blacklists/<账户名称>.json
```

面板中的黑名单只用于用户查看和编辑。保存面板时，脚本会同步更新本地 JSON 文件和当前配置组的 `settings.blacklist`；下次启动仍以本地文件为准，不从旧配置恢复本地文件。

黑名单同时作用于：

- 模板匹配拾取排除。
- 路线文件路径、文件名和普通描述的文本排除。
- 效率计算，黑名单材料权重为 `0`。

“禁用名称关键词”只检查路线文件路径、文件名和普通描述，不影响拾取，也不参与材料权重计算。两者都不会把 `【材料*数量】` 声明当作普通描述排除条件。

### 4. 添加材料模板

将 PNG 模板放入 `assets/targetItems/保留/` 或其子目录。该目录已列入 `manifest.json` 的 `saved_files`，更新脚本时会作为用户数据保留。

添加模板时建议：

1. 使用游戏拾取列表中的材料名称区域制作模板。
2. 保持截图尺寸、显示比例和实际运行环境一致。
3. 使用准确的材料名称作为文件名。
4. 如果交互名称与获得物品名称不同，可用父目录 `[实际材料名]` 声明别名。
5. 如需自动 CD，再在 `assets/materialCdMap.json` 中添加对应材料。

## 七、数据文件与旧配置迁移

### 1. 文件结构

```text
采集cd管理/
├─ main.js
├─ manifest.json
├─ settings.json
├─ pathing/
│  ├─ 采集cd管理路线工具.exe
│  └─ README.md
├─ schedules/
├─ subJs/
│  └─ _managed/
├─ route-manager/
│  ├─ mappings.json
│  └─ sync-state.json
├─ record/
│  └─ <账户>/
│     ├─ record.json
│     └─ 拾取记录.json
├─ blacklists/
│  └─ <账户>.json
└─ assets/
   ├─ config.html
   ├─ materialCdMap.json
   ├─ pinyin-pro.js
   └─ targetItems/
```

主要文件用途：

- `settings.json`：只包含 HTML 配置面板入口开关。
- `pathing/`：路线和 Schedule 文件，并随附路线管理器 EXE 及其说明；脚本只扫描其中的 JSON，不会执行 EXE 或读取该 README。
- `schedules/`：外部路线工具维护的 Schedule 源文件；需映射到 `pathing/` 后才会执行。
- `subJs/_managed/`：外部路线工具完整导入的 Schedule 子 JS。
- `route-manager/`：外部路线工具的路径组映射和同步状态。
- `record/<账户>/record.json`：路线 `cdTime` 和最近最多 7 条有效运行历史。
- `record/<账户>/拾取记录.json`：每日材料数量，最多保留 30 个统计日。
- `blacklists/<账户>.json`：当前账户的本地黑名单来源。
- `assets/materialCdMap.json`：材料名称与 CD 类型映射。
- `assets/targetItems/`：模板匹配图片及材料别名来源。
- `assets/config.html`：HTML 配置面板。
- `assets/pinyin-pro.js`：材料名称拼音补全。

`manifest.json` 会保留 `pathing/`、`record/`、`blacklists/`、`assets/targetItems/保留/`、`subJs/`、`schedules/` 和 `route-manager/`。`settings.json` 等脚本资源仍以仓库版本为准。

### 2. 业务配置存储

HTML 面板把业务配置写入当前 BetterGI 配置组的 `settings` 对象：

- `taskList` 以 `|` 分隔任务 ID 与名称，出现顺序就是任务优先级。
- 每个任务使用 `task-<ID>-<字段>` 保存，例如 `enabled`、`allowedGroups`、`allowReopen`、`onlyRelatedRoutes`、`dailyTarget`、`oneTimeTarget`、`sortMode`、`thresholdEfficiency`、`timeRule` 和 `durationMinutes`。
- `pathGroupList` 以 `|` 分隔路径组 ID 与名称。
- 每个路径组使用 `pathGroup-<ID>-<字段>` 保存，例如 `folder`、`cdType`、`partyName` 和 `setTimeMode`。
- 基础设置使用 `infoFileName`、`defaultParty`、`operationMode`、`materialValue`、`pickup_Mode`、`findFInterval`、`blacklist`、`disableNameKeywords`、`disableSecondCheck` 和 `disableXYCheck` 等字段。
- 食材加工使用 `processingIngredient` 和 `checkInterval`。

这些字段用于说明数据结构，日常配置应通过 HTML 面板完成。删除任务或路径组时，面板会同步更新列表并清理对应的动态字段。

### 3. 运行记录

- 普通路线运行超过 10 秒时写入历史，最近保留 7 条。
- BetterGI 返回布尔型 `runFile().success` 时，脚本直接采用宿主结果。
- 只有宿主没有返回布尔结果时，才回退到终点坐标校验。
- `disableXYCheck=true` 只跳过上述回退校验，并在该回退路径中视为成功、允许记录 CD。
- 执行失败的路线会在本次脚本运行中排除，不写入成功 CD。
- 索引按路线文件名匹配，不按完整路径匹配，因此应避免重名路线。

### 4. 旧配置迁移

仅当新版 `pathGroupList` 或 `taskList` 不存在时，脚本才执行旧配置迁移：

- 旧每日优先目标迁移为“每日采集”任务，允许全部路径组，默认按效率降序。
- 旧一次性优先目标迁移为“一次性采集”任务，允许全部路径组，默认按效率降序，并关闭“允许再次开启”。
- 每个旧路径组迁移为一个独立任务，沿用旧全局 `sortMode` 和对应路径组的最低效率。
- 旧全局禁止运行时间迁移到各个任务。
- 旧全局调节游戏时间迁移到各个路径组。
- 旧材料加权规则迁移为基础设置中的材料价值倍数。
- `groupCount=0` 会保持为零路径组，不会自动扫描全部目录。
- 全新安装且完全没有旧 `groupCount` 时，才会按 `pathing` 一级目录自动创建路径组。

迁移完成后，旧调度字段会从 `settings` 中移除，后续由新版任务和路径组配置负责运行。

## 八、Schedule 文件

路线 JSON 根对象同时包含 `schedule` 和 `tasks` 数组时，脚本会按 Schedule 执行。Schedule 文件本身仍作为路径组中的一条路线参与任务筛选、排序和 CD 管理。

### 1. 最小示例

```json
{
  "schedule": [
    { "action": "start", "task": "采集路线", "count": 1 },
    { "action": "start", "task": "子脚本" },
    { "action": "wait", "task": "子脚本" }
  ],
  "tasks": [
    {
      "name": "采集路线",
      "type": "autopathing",
      "filePath": "pathing/区域特产/蒲公英籽01.json"
    },
    {
      "name": "子脚本",
      "type": "js",
      "filePath": "subJs/示例脚本/",
      "settings": {},
      "async": true
    }
  ]
}
```

### 2. `schedule` 动作

| 字段 | 必填 | 说明 |
|---|---|---|
| `action` | 是 | `start` 启动任务，`wait` 等待异步任务。 |
| `task` | 是 | 对应 `tasks` 中的唯一任务名称。 |
| `count` | 否 | `start` 的执行次数，默认 `1`。 |

### 3. `tasks` 定义

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | Schedule 内的任务名称。 |
| `type` | 否 | `js`、`autopathing` 或 `keymousescript`；省略时按 `js`。大小写不敏感。 |
| `filePath` | 是 | 按当前脚本工作目录解释的路径。 |
| `settings` | 否 | 仅 `js` 任务使用，传给子脚本入口。 |
| `async` | 否 | `true` 时 `start` 不等待完成，可由后续 `wait` 等待；默认 `false`。 |

`js` 的 `filePath` 应指向包含 `manifest.json` 的脚本目录。Schedule 执行期间仍会启动当前选择的拾取伴随任务，包括模板匹配拾取或 BGI 原版拾取。

### 4. 外部路线工具与声明索引

随附的 `pathing/采集cd管理路线工具.exe` 可以维护文件夹和单个 Schedule 到路径组的映射，也可以根据子 JS 的 `manifest.json` 与 `settings.json` 生成最简单的单 JS Schedule。Schedule 源文件保存在 `schedules/`，导入的子 JS 保存在 `subJs/_managed/`，映射后才会复制到 `pathing/` 参与调度。

工具更新路径组时会在组根目录生成 `route-index.json`。该文件只保存组内实际 JSON 文件的相对路径与 `info.description`。脚本启动时先读取各组 index，并用其中的路径推导需要枚举的目录，再通过 `ReadPathSync` 校验本组实际文件；初始化与调度器共用生成的路线快照。声明与实际文件一致时不会读取路线 JSON 正文；只有声明缺失或不一致的实际路线才回退读取完整 JSON，多余声明被忽略，索引损坏时该组全部回退原读取逻辑。`route-index.json` 本身不会作为路线执行。

## 九、脚本运行逻辑

<details>
<summary>启动与配置读取</summary>

脚本先加载任务和路径组配置；如果缺少新版列表则执行一次旧配置迁移。勾选 HTML 入口时，脚本打开面板并等待保存；未勾选时直接读取已保存配置。随后加载账户黑名单、材料 CD 表、材料模板、路线索引和拾取记录。

</details>

<details>
<summary>路线筛选与执行</summary>

调度器按任务顺序检查退出条件，合并允许路径组的路线，然后应用本次失败记录、路线排除、相关材料、CD 和效率阈值。筛选结果按任务排序方式统一排序，每次只执行第一条路线，之后重新从首个任务检查。

执行路线前，脚本按路径组切换队伍、检查食材加工并按需调整游戏时间。路线执行期间启动所选拾取任务，并在结束时回收拾取记录。

</details>

<details>
<summary>结果与记录更新</summary>

路线成功后，脚本按路径组 CD 类型更新 `record.json`，把拾取写入每日记录，并同步扣减所有任务的一次性目标。失败路线加入本次运行的排除集合。完成一条路线后调度器重新从第一个任务开始；完整一轮没有路线执行时结束。

</details>

## 十、故障排查

### HTML 面板没有打开

- 确认自定义配置中的“启动时打开 HTML 配置面板”已勾选。
- 确认 BetterGI 版本不低于 `0.62.0`。
- 入口开关关闭时脚本会直接使用已保存配置；需要编辑时应重新勾选。

### 保存配置失败

- 账户名称不能为空，且不能包含 Windows 文件名非法字符。
- 路径组名称不能为空，同一一级文件夹不能分配给多个路径组。
- 任务名称不能为空，选择的路径组必须仍然存在。
- 材料目标使用 `材料*数量+材料*数量`。
- 材料价值使用 `材料*倍数，材料*倍数`。
- 拾取识别间隔必须在 `16` 至 `200` 之间，食材加工识别间隔必须为正数。

### 任务没有执行路线

依次检查：

1. 任务是否启用，是否已在本次运行中因 `allowReopen=false` 被禁用。
2. 任务是否选择了有效路径组，路径组是否选择文件夹和非空 CD 类型。
3. 当前时间是否命中禁止运行范围，目标是否已经完成，时长是否已达到上限。
4. 路线是否被黑名单或禁用名称关键词排除。
5. 开启“仅执行相关路线”时，路线名称、路径、描述或历史中是否包含未完成目标材料。
6. 路线是否仍在 CD，或效率是否低于任务阈值。
7. 路线是否已经在本次运行中失败。

### CD 没有更新

- 检查 BetterGI 返回的路线执行结果是否为成功。
- 宿主没有返回布尔结果时，检查终点坐标回退校验。
- 固定 CD 由路径组直接决定；`不指定` 依赖本次回收的拾取材料。
- BGI 原版拾取模式下，旧版 BetterGI 缺少 `getPickRecords()` 时无法按材料统计。
- 强制刷新成功后会自动恢复普通模式；如果日志提示索引写入失败，应先处理文件写入问题。

### 拾取或统计不正确

- 模板匹配模式检查游戏分辨率、缩放、模板文件和识别间隔。
- 检查材料是否位于账户黑名单。
- 交互名称与获得物品名称不一致时，检查模板目录中的 `[材料名]` 别名。
- BGI 原版拾取由 BetterGI 自身控制，本脚本黑名单不会阻止原版拾取器交互。
- 每日统计以 UTC+8 凌晨 4 点为边界，不是自然日 00:00。

### 路线效率未知或异常

- 至少 3 条有效历史后才使用历史平均效率。
- 历史不足时，检查路线描述中是否有可解析的材料和用时声明。
- 检查材料价值倍数、黑名单和任务的“仅执行相关路线”状态。
- 同名路线会共用历史，应确保文件名唯一。
