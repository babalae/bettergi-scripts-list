# 背包扫描

扫描原神背包里各页签的物品，认出每种东西有多少个，写一份文字报告并留一份历史记录；
填了关注材料的话，还会把这些物品的数量一起推一条通知。

物品靠图标模板比对认出来，数量先按数字模板比对、读不出再走 OCR 兜底。
这也是它对分辨率挑剔的原因：所有取样坐标都是按 1920×1080 定的。

## 运行前

- 游戏分辨率必须是 1920×1080。不是这个分辨率时坐标会整体错位，结果基本不能看。

## 怎么用

将本脚本添加进配置组，默认设置即可全量扫描。
也可以按自己的情况改下面的设置。跑完看 `record/` 里的文件，
日志和通知里也会带一句统计（各页认出多少种）。

## 设置项

- **`账户名称`**：账户名称，用来给不同游戏账号分开存记录，
  结果会写进 `record/<账户名>/`。默认「默认账户」，单账号不用改。
- **`关注材料`**：想单独看数量的材料名，多个用中文逗号分开
  （英文逗号、顿号、分号、换行也行）。命中的物品会发通知，不填就只发统计行。
- **`扫描范围`**：扫描范围，六项，默认全勾。取消勾选就不扫对应项。
- **`绝版料理`**：绝版料理清单，勾选你确实拥有的。
  取消勾选会把这个料理从识别名单里剔除，但是如果三种品质中你有任意一种就要勾选。
  默认全勾，详见「常见问题」。
- **`调试`**：默认关。打开后会在 `record/<账户名>/` 下多建一个
  `scan-<时间戳>/` 目录，存每屏截图和逐格识别明细。只在排查识别错误时开，
  会明显增加磁盘占用和少量耗时。

## 扫描范围

| 名字 | 对应背包页签 | 统计方式 |
| --- | --- | --- |
| 养成道具 | 养成道具 | 整页按模板逐个识别 |
| 食物 | 食物 | 整页按模板逐个识别 |
| 材料 | 材料 | 整页按模板逐个识别 |
| 锻造矿 | 武器 | 只数固定名单 |
| 狗粮经验 | 圣遗物 | 只数固定名单 |
| 抽卡资源&摩拉 | 贵重道具 | 只数固定名单 |

前三个页签按模板库逐格统计，名单里没扫到的物品也会列成 `×0`，方便看出少了什么。
后三个页签不扫整页，只按一份固定名单找几样东西：武器页找三种精锻用矿，
圣遗物页找祝圣精华、祝圣油膏，贵重道具页找无主的星辉／星尘、纠缠之缘、相遇之缘、
原石和摩拉。所以「抽卡资源&摩拉」只报这几项属于正常，不是漏扫。

## 结果放在哪

`record/` 由脚本自己创建，不用手动建，按账户分目录：

```
record/<账户名>/
├── 扫描结果.txt            本次报告，每次覆盖
├── 扫描结果历史记录.txt    每次一段，最多留最近 30 次
└── scan-<时间戳>/          只在 debug 开启时生成
    ├── pages/              每屏截图，如 材料_p000.png
    └── records.json        逐格识别明细，每行一条 JSON
```

`扫描结果.txt` 里有时间、耗时、各页统计和逐项数量（数量没读出来显示 `?`），
另有【问题】段放未识别格子、拖拽失败等异常。
历史记录是纯文本分段，段头形如
`===== 第 3 次 · 2026-11-14 22:00:01 · 耗时 41.2s =====`，最新一次排在最前面。

## 常见问题

### 某种物品没被识别出来

先看 `扫描结果.txt` 的【问题】段：未识别的格子会列出来，并写明它前后是什么物品，
方便你对照背包找位置。常见原因：

- 模板库还没收录这个物品（新版本新增的东西）。报告会提示
  「可能是模板库尚未包含它们，请更新脚本或等待作者更新」。
- 分辨率不是 1920×1080，坐标整体错位。先看日志有没有报错。
- 数量数字没读出来。该项数量显示 `?`，不会写为 0。
- 绝版料理的勾选不对，见下一条。

如果确实觉得脚本有问题，请打开 `debug` 重跑一次，
并将最新时间 `debug` 文件夹附带两份结果文件打包发送给作者。
作者在BGI官方V8、V14群，可以来这两个群撅作者

### 绝版料理怎么处理

在「绝版料理」里只勾你确实拥有的那几样。取消勾选就是告诉脚本「我没有」，
脚本会把它从识别名单里剔掉。默认是全勾的；如果你其实一样都没有，保持全勾只会多花一点时间，
把没有的都取消更快。

### `debug` 开关怎么用

平时关着。遇到「明明有却没扫到」「数量不对」「报告里冒出未识别」时打开，
重跑一次，然后看 `record/<账户名>/scan-<时间戳>/`：`pages/` 是每屏截图，
`records.json` 每行一条 JSON，记着该格的候选、分数和数量。
