# 冰造物 NPC 点赞自动化

作者：一只低熵体  
版本：`1.3.0`<br>
全部路线预计总点赞：`48`

脚本使用 BetterGI 地图追踪前往至冬 NPC 工位，自动完成两次冰造物放置、点赞等待、删除和最终清理。脚本不读取游戏内存，不联网，也不使用第三方程序、KeyMouseScript、OCR 或点赞图像识别。

## 使用条件

- BetterGI `0.64.0` 或更高版本；
- 简体中文游戏客户端；
- 16:9 游戏画面，至少 `1920×1080`；
- BetterGI 截图方式设为 `BitBlt`；
- 小地图保持“锁定方向”；
- 原神水平、垂直镜头灵敏度均保持默认值 `3`；
- 保持默认亮度并关闭 HDR、显卡滤镜等画面效果；
- 冰造物快捷键为 `T`，相关区域和传送锚点已解锁；
- 运行期间不要操作键盘和鼠标。

## 任务与路线解锁

- 完成三个聚所任务的共同第四幕“雪后曙光”后，Point 06、07、09、10 一带的 NPC 通常会显示；Point 08 的 NPC 显示还涉及现实时间第二天的“新雪来客”。参考：[《雪后曙光》教程](https://www.bilibili.com/video/BV172bX6XEPm/)、[《新雪来客》教程](https://www.bilibili.com/video/BV1nqbX6fEDS/)。
- NPC 未显示并不必然意味着无法获得点赞：部分账号在未完成任务、NPC 不可见时，放置冰造物后仍实测获得点赞。脚本不会识别任务进度或实际点赞，请以自己的运行结果为准。
- 所有路线需要相关区域和普通传送锚点已解锁。Point 12 会优先尝试“特殊招募计划”任务入口近路；若传送或落点核对失败，会自动改走从普通锚点出发的完整路线，因此不要求解锁任务入口传送。

## 点赞机制

以下规则来自 [breadgrocery 大佬在 PR #3613 中分享的解包配置资料](https://github.com/babalae/bettergi-scripts-list/pull/3613)，并非脚本读取游戏数据所得：

- 冰造物在 NPC 出生点或活动中心约 `15` 米范围内时，可以触发点赞判定；建筑、墙体遮挡或任务使 NPC 不显示，不一定影响点赞。
- 配置中存在可点赞的 NPC，不代表现场一定能取得点赞：有些场景或地块无法放置冰造物。路线表只列出本脚本已收录的工位，每位 NPC 按两次放置预计获得 `2` 赞。
- 脚本不会检测 NPC、判定半径或实际点赞；若游戏版本或场景发生变化，请以实机结果为准。

## 使用方法

1. 在 BetterGI 中订阅或导入脚本。
2. 右键脚本，打开“修改 JS 自定义配置”。
3. 在“启用路线”多选框中选择需要执行的 Point；默认全选 Point 01～12，可按账号情况取消。
4. 将脚本加入调度器并运行。首次测试建议使用“推荐顺序”。

新配置默认执行全部 12 个 Point，路线标签合计预计 `48` 赞；实际点赞数量不做视觉识别。从旧版升级且保留了逐点开关设置时，脚本会沿用旧选择，请在配置页检查“启用路线”。

### 车站连续路线

- Point 07、08、09 都开启时：`Point 07 → Point 08 → Point 09`；Point 09 关闭时在 Point 08 结束；
- Point 08 关闭、Point 09 开启时：自动改走 `Point 07 → Point 09` 完整备用路线；
- Point 07 关闭时：依赖当前位置的 Point 08、09 会自动跳过。

连续路线组不会被传送或热能恢复流程拆开。

## 运行模式

- **推荐顺序**：默认模式，按 `01→02→03→06→05→04→07→08→09→10→11→12` 执行；关闭的路线会从顺序中跳过，07～09 仍作为连续组；
- **高点赞优先**：执行全部已启用路线，并按路线组预计点赞量排序；
- **高收益精简（6赞及以上）**：只执行预计点赞达到 `6` 的路线组。

全部路线启用时，高收益精简模式会执行 Point 07～09 连续组（12 赞）、Point 02（8 赞）、Point 01（6 赞）和 Point 10（6 赞），合计预计 `32` 赞。

## 热能与镜头

脚本启动时会先返回固定七天神像恢复热能；进入神像范围后会自动恢复，所有目标环境均无需按 `F`。Point 01～12 **全部启用**时，三种运行模式都只在开局回神像一次；关闭任意路线后，脚本内部改为每完成 `4` 个 Point 返回神像。连续路线组不会拆开，若下一个组超过剩余额度，会在组开始前提前恢复。热能策略由脚本自动选择，无需用户设置。

按录制路线，Point 06、07、10、11 会在放置冰造物前经过热能恢复设施，预计每次恢复 `60` 点热能；每个 Point 的两次放置预计消耗 `10` 点。推荐顺序把 Point 06 提前到第四个执行，以便更早经过恢复设施。脚本**不检测实际热能或沿途恢复是否触发**；全选时仅开局回神像的策略依赖这些恢复设施正常生效。

每个 Point 到位后，路线末尾的 `orientation` 负责确定水平视角；脚本再将垂直镜头推到上限，随后按自定义配置中的“冰造物放置镜头角度”向下移动，默认值为 `7500`。

检测到 `3840×2160` 或更高分辨率时，脚本默认在按 `T` 后额外等待 `800ms`。其他分辨率如果也出现界面动画未完成便点击的问题，可以手动启用相同时序补偿。

## 常用设置

| 设置 | 默认值 | 建议 |
| --- | ---: | --- |
| 路线运行模式 | 推荐顺序 | 首次测试保持默认 |
| 启用路线（多选） | Point 01～12 全选 | 可按账号情况取消；Point 08、09 依赖 Point 07 |
| 冰造物放置镜头角度 | 7500 | 控制最终放置位置 |
| 强制启用 4K 时序补偿 | 关闭 | 非 4K 出现点击过早时开启；4K 会自动启用 |

## 故障排查与限制

- 多条路线同时出现传送点击偏移时，先完整退出并重启 BetterGI；
- 地图追踪反复摇摆时，确认 `BitBlt`、小地图锁定方向和稳定帧率，条件允许时可尝试 `2560×1440`；
- 脚本中途停止或报错后，请人工确认现场是否残留冰造物，并按 `T` 退出造物界面；
- Point 12 的近路会先单独传送并核对小地图位置；无法确认落点时会保守地走普通锚点路线。自动回退尚需在未解锁任务入口的账号上实机验证；
- 日志中的预计点赞来自路线标签，脚本不会视觉识别实际点赞、热能数值或删除结果。
