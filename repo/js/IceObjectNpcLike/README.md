# 冰造物 NPC 点赞自动化

作者：一只低熵体  
版本：`1.1.0`  
全部路线预计总点赞：`36`

脚本使用 BetterGI 地图追踪前往至冬 NPC 工位，自动完成两次冰造物放置、点赞等待、删除和最终清理。脚本不读取游戏内存，不联网，也不使用第三方程序、KeyMouseScript、OCR 或点赞图像识别。

## 使用条件

- BetterGI `0.64.0` 或更高版本；
- 简体中文游戏客户端；
- 16:9 游戏画面，至少 `1920×1080`；
- BetterGI 截图方式设为 `BitBlt`；
- 小地图保持“锁定方向”；
- 原神水平、垂直镜头灵敏度均保持默认值 `3`；
- 保持默认亮度并关闭 HDR、显卡滤镜等画面效果；
- 冰造物快捷键为 `T`，相关区域和传送锚点已解锁；
- 运行期间不要操作键盘和鼠标。

## 任务前置

- **Point 06、07、09**：需要完成三个聚所任务的共同第四幕“雪后曙光”，可用成就“睁开被逸夜合拢的眼睛”确认。参考：[《雪后曙光》教程](https://www.bilibili.com/video/BV172bX6XEPm/)。
- **Point 08**：除“雪后曙光”外，还需在现实时间第二天完成“新雪来客”。参考：[《新雪来客》教程](https://www.bilibili.com/video/BV1nqbX6fEDS/)。

Point 06～09 默认关闭，请根据任务进度启用。

## 使用方法

1. 在 BetterGI 中订阅或导入脚本。
2. 右键脚本，打开“修改 JS 自定义配置”。
3. 按任务进度启用路线；未完成前置任务时保持 Point 06～09 关闭。
4. 将脚本加入调度器并运行。首次测试建议使用“按 Point 编号”。

默认启用 Point 01～05，预计获得 `22` 赞；完成“雪后曙光”并启用 Point 06、07、09 后预计获得 `30` 赞；再启用 Point 08 后，全部路线预计获得 `36` 赞。

### 车站连续路线

- Point 08 开启时：`Point 07 → Point 08 → Point 09`；
- Point 08 关闭时：自动改走 `Point 07 → Point 09` 完整备用路线；
- Point 07 关闭时：依赖当前位置的 Point 08、09 会自动跳过。

连续路线组不会被传送或热能恢复流程拆开。

## 运行模式

- **按 Point 编号**：默认模式，适合首次测试；
- **高点赞优先**：执行全部已启用路线，并按路线组预计点赞量排序；
- **高收益精简（6赞及以上）**：只执行预计点赞达到 `6` 的路线组。

全部路线启用时，高收益精简模式会执行 Point 07～09 连续组（10赞）、Point 02（8赞）和 Point 01（6赞），合计预计 `24` 赞。

## 热能与镜头

脚本启动时会先返回固定七天神像恢复热能，默认每完成 `4` 个 Point 再恢复一次。若下一个连续组的长度超过剩余额度，会在组开始前提前恢复。

每个 Point 到位后，路线末尾的 `orientation` 负责确定水平视角；脚本再分 `4` 次将垂直镜头推到上限，随后向下移动 `7500`。如个别点位需要调整，可在自定义配置中填写水平或垂直覆盖，例如 `02=6100,05=5900`。

检测到 `3840×2160` 或更高分辨率时，脚本默认在按 `T` 后额外等待 `800ms`。其他分辨率如果也出现界面动画未完成便点击的问题，可以手动启用相同时序补偿。

## 常用设置

| 设置 | 默认值 | 建议 |
| --- | ---: | --- |
| 路线运行模式 | 按 Point 编号 | 首次测试保持默认 |
| 每完成几个 Point 恢复热能 | 4 | 推荐保持 4 |
| 镜头向上归一化次数 | 4 | 未到顶时逐次增加 |
| 从垂直上限向下移动量 | 7500 | 控制最终放置位置 |
| 两次点赞等待 | 各 800ms | 点赞未刷新时增加 |
| T 后额外等待 | 800ms | 4K 自动启用 |

## 故障排查与限制

- 多条路线同时出现传送点击偏移时，先完整退出并重启 BetterGI；
- 地图追踪反复摇摆时，确认 `BitBlt`、小地图锁定方向和稳定帧率，条件允许时可尝试 `2560×1440`；
- 脚本中途停止或报错后，请人工确认现场是否残留冰造物，并按 `T` 退出造物界面；
- 日志中的预计点赞来自路线标签，脚本不会视觉识别实际点赞、热能数值或删除结果。
