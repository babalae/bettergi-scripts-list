# 锄地一条龙

## 一、功能与运行前提

本脚本用于在 BetterGI 中执行地图追踪路线，并提供路线选择、路径分组、物品拾取、物品黑名单、药品检测、晶蝶辅助传送、泥头车和运行记录等功能。

- 依赖 BetterGI 的 JavaScript 脚本、地图追踪、图像识别和实时触发器接口。
- 主要识别区域按照 `1920×1080` 游戏窗口制作，其他分辨率未经过同等验证。
- 运行路线时需要使用当前 BetterGI 版本能够识别的地图追踪文件和战斗策略。
- 脚本通过 BetterGI 配置组启动，配置组中的队伍、战斗策略和其他功能可能影响运行结果。
- 图像识别效果可能受到窗口尺寸、缩放、HDR、滤镜、插帧和其他显示设置影响。
- 脚本不判断角色组合是否合理，也不会因为角色组合触发提示或终止运行。`validateTeamMembers` 仅用于确认用户指定的角色是否位于当前队伍中。

## 二、快速上手

### 正常模式

最简配置如下：

- `operationMode`：`运行锄地路线`
- `groupIndex`：`路径组一`
- `accountName`：填写账户名称，单账户可使用默认值
- `targetEliteNum`：`400`
- `targetMonsterNum`：`2000`
- `pickup_Mode`：按需求选择模板匹配拾取、BGI 原版拾取或不拾取

需要脚本切换队伍时填写 `partyName`，否则留空。首次运行可以先选择“调试路线分配”查看路线分组，再选择“运行锄地路线”。

### 仅指定怪物模式

最简配置如下：

- `operationMode`：`启用仅指定怪物模式`
- `targetMonsters`：填写目标怪物名称，多个名称使用中文逗号分隔
- `partyName`：按需填写队伍名称
- `pickup_Mode`：按需求选择拾取方式

该模式会在路线文件名和路线描述中匹配目标怪物，只运行匹配到的路线，不使用普通路线组合选择逻辑。

## 三、配队建议

以下仅作建议，并非强制要求，基于开发时的 BGI 与原神版本，随着版本更新可能过时，一切以用户实际运行情况为准。

### 盾奶位

可以考虑携带盾位和治疗位，以提高路线运行的稳定性。不建议同时携带两个盾位，双盾的盾量不会叠加。

### 自动索敌角色

可以考虑使用自动索敌，且无需位移或位移可控的角色：

- 芙宁娜：索敌距离 25 m。
- 爱可菲：索敌距离 15 m。
- 伊涅芙：索敌距离 10 m，双中心索敌。
- 莉奈娅：索敌距离 25 m。
- 玛薇卡：火环索敌距离 15 m。
- 桑多涅：BetterGI 本体自带特化，使用 `charge` 命令即可直接锁头，但需要配合队友触发对应星烁状态。

### 拾取角色

包含精英的分组可以考虑携带万叶或琴以提高拾取率，相关分组说明见[进阶使用技巧中的分组用途](#分组的用途)。

### 推荐配队

以下配队仅为主观推荐，具体以实际运行效果为准。

<details>
<summary>推荐配队组合与特点</summary>

- `茜芙爱万`：茜特菈莉、芙宁娜、爱可菲、枫原万叶。可以稳定冻结，生存能力较高，且没有雷、火伤害不会转化蕈兽，但伤害可能较低。
- `火芙盾万`：玛薇卡、芙宁娜、茜特菈莉/尼可/伊涅芙、枫原万叶。火神数值较高且具备较强的跑图性能，可大幅缩减跑图时间；但缺少治疗位，可能降低稳定性。
- `万芙莉机`：枫原万叶、芙宁娜、莉奈娅、伊涅芙。月反应配队，新时代体系数值较高，且有稳定的盾奶。
- `桑机爱万`：桑多涅、伊涅芙、爱可菲、枫原万叶。木偶的可用配队之一，可以稳定触发星超导；木偶本身处理次数盾怪物具有一定优势。

</details>

## 四、进阶使用技巧

### 分组的用途

分组可以让不同路线使用不同的队伍、战斗策略、拾取设置或运行时段。路线总目标仍然只在路径组一的路线选择配置中设置，分组发生在路线组合选择之后。

<details>
<summary>示例：将 400 精英和 2000 小怪拆分运行</summary>

按每只精英 2% 概率掉落价值 2520 的四星狗粮、8% 概率掉落价值 1260 的三星狗粮计算，狗粮期望价值为：

`0.02 × 2520 + 0.08 × 1260 = 151.2`

因此，精英路线存在额外的狗粮收益。如有条件，精英路线尽量携带万叶或琴以拾取狗粮；实际效果与路线、队伍和战斗策略有关，以用户自己的运行体验为准。小怪路线没有上述狗粮额外收益，无需刻意拾取。

具体操作：

1. 在路径组一配置组中填写 `targetEliteNum=400`、`targetMonsterNum=2000`，并设置 `accountName`、优先关键词、排除关键词、排序和自动优化选项。
2. 将 `tagsForGroup2` 填写为 `小怪`。脚本会把自动带有 `小怪` 标签的纯小怪路线分配到路径组二。
3. 未命中路径组二至路径组十标签的路线进入路径组一。由于脚本不会自动添加通用“精英”标签，路径组一可能包含混合路线，应通过调试输出确认。
4. 建立两个 BetterGI 配置组，分别将 `groupIndex` 设置为“路径组一”和“路径组二”，并使用相同的 `accountName`。两个配置组可以分别设置队伍、战斗策略、拾取方式和时间限制。
5. 选择“调试路线分配”确认 `group1` 和 `group2` 的路线及统计，再按需要运行两个路径组。多个路径组的执行顺序由 BetterGI 配置组或调度设置决定。

不要将总目标分别填写成路径组一的 `400-0` 和路径组二的 `0-2000`。这两个字段表示路线组合的整体目标，不是每个路径组的独立目标。

</details>

<details>
<summary>添加自定义路线</summary>

支持标准 BetterGI 地图追踪 JSON 格式。建议先使用 BetterGI 地图追踪编辑器录制或导出路线，再将文件放入 `pathing/0-保留/` 或其子目录。路线文件的最小结构如下，`positions` 中的位置点应由地图追踪编辑器生成：

```json
{
  "info": {
    "name": "自定义路线",
    "type": "collect",
    "version": "1.0",
    "description": "路线信息：该路线预计用时60秒，预计收入0摩拉，包含以下怪物：4只精英传奇倍率三。",
    "map_name": "Teyvat",
    "bgi_version": "0.45.0",
    "tags": []
  },
  "positions": [
    {
      "id": 1,
      "x": 0,
      "y": 0,
      "action": "",
      "action_params": "",
      "move_mode": "walk",
      "type": "teleport"
    },
    {
      "id": 2,
      "x": 10,
      "y": 10,
      "action": "",
      "action_params": "",
      "move_mode": "walk",
      "type": "path"
    }
  ]
}
```

脚本对路线文件的使用规则：

- 根对象需要包含 `info` 和 `positions`，位置点、移动模式、动作和动作参数应符合 BetterGI 地图追踪格式。路线能否正常执行仍由 BetterGI 版本和路线内容决定。
- `info.description` 中使用 `预计用时数字秒` 提供预计时长，例如 `预计用时60秒`。
- 怪物信息使用 `包含以下怪物：数量只怪物名称、数量只怪物名称。`，例如 `包含以下怪物：4只精英传奇倍率三。`。怪物名称必须与 `assets/monsterInfo.json` 中的名称一致，否则不会计入路线的怪物数量和收益。
- `info.tags` 使用字符串数组填写标签，例如 `["水免", "高危"]`。标签用于优先、排除和路径组分配；自定义标签也可以通过路径或描述中的文字参与匹配。
- `info.map_name`、`info.map_match_method` 等地图字段会随路线传递给 BetterGI，建议保留编辑器导出的值。

添加后可以先使用“调试路线分配”确认路线是否被读取、统计和分组。

</details>

<details>
<summary>添加自定义模板图片</summary>

将 `.png` 文件放入 `assets/targetItems/其他/保留/` 或其子目录。模板文件名会作为物品名称参与识别和拾取历史记录；文件名中的括号数值可用于设置模板匹配阈值。使用模板匹配拾取模式时，脚本会在启动阶段加载这些模板。

模板图片可以从以下来源获取：

1. 自行截图：从游戏中的拾取列表截取物品名称区域，截图时应注意位置、大小和显示比例，尽量与运行时画面保持一致，并保存为 `.png`。
2. 采集 cd 管理：从该脚本的 `assets/targetItems/` 目录中获取需要的模板图片，再复制到本脚本的自定义模板目录。
3. 获取最新模板：前往[交流与相关项目](#八交流与相关项目)中的 QQ 群 `1109232869` 获取。

</details>

<details>
<summary>使用盗宝团好感任务补足小怪</summary>

盗宝团好感任务单次可以击杀 7 只小怪，相比常规小怪路线通常具有更高的单位任务效率。该任务最多可运行 50 次，共计 350 只小怪。

如果需要提高整体运行效率，可以在调度末尾添加一个战斗好感任务，并勾选“无经验和摩拉时提前结束”。同时将本脚本的目标设置为精英 400、小怪 1700，即 `400-1700`，把剩余的小怪目标交给好感任务完成。

</details>

## 五、配置项说明

配置项按功能分组列出，字段名称与 `settings.json` 一致。每项默认折叠，点击标题可查看详细说明。

### 执行设置

<details>
<summary><code>operationMode</code>：执行模式</summary>

可选值：

- `运行锄地路线`：按路线选择和路径组配置执行路线。
- `调试路线分配`：只进行路线选择和分组，并输出调试结果。
- `强制刷新所有运行记录`：重新初始化当前账户的路线记录，不执行路线。
- `启用仅指定怪物模式`：只运行名称或描述中包含目标怪物的路线。

</details>

<details>
<summary><code>groupIndex</code>：执行的路径组</summary>

选择当前运行的路径组，范围为“路径组一”至“路径组十”。脚本每次启动只处理当前选择的路径组。使用路径组二至十时，路线选择配置从同账户的路径组一配置文件读取。

</details>

<details>
<summary><code>partyName</code>：路径组使用的队伍</summary>

填写 BetterGI 中的队伍名称。脚本会在适用的执行模式下尝试切换到该队伍。留空时不执行指定队伍切换。

</details>

<details>
<summary><code>validateTeamMembers</code>：队伍成员确认</summary>

填写需要确认的角色名称，多个角色使用中文逗号分隔。切换队伍后，脚本会确认这些角色是否存在；确认失败时会重新尝试切换，最多重试 3 次。留空时不执行角色成员确认。该配置不评价队伍组合是否合理。

</details>

<details>
<summary><code>sortMode</code>：组内路线排序</summary>

可选值：

- `原文件顺序`：按路线文件名顺序运行。
- `效率降序`：按脚本计算的路线效率排序。
- `高收益优先`：将带有高收益标记的路线排在前面。

默认值：`高收益优先`。

</details>

### 拾取设置

<details>
<summary><code>pickup_Mode</code>：拾取模式</summary>

可选值：

- `模板匹配拾取，拾取狗粮和怪物材料`：加载对应目录下的物品模板进行识别。
- `模板匹配拾取，只拾取狗粮`：只加载狗粮模板。
- `bgi原版拾取`：由 BetterGI 的 `AutoPick` 实时触发器处理。
- `不拾取任何物品`：不启动脚本模板拾取。

默认值：`模板匹配拾取，拾取狗粮和怪物材料`。

</details>

<details>
<summary><code>onlyRelatedItems</code>：只识别路线相关材料</summary>

模板匹配拾取时，根据当前路线包含的怪物筛选怪物材料模板。只拾取狗粮模式没有可筛选的怪物材料；BGI 原版拾取和不拾取模式下该选项不生效。

默认值：关闭。

</details>

<details>
<summary><code>disableSecondCheck</code>：关闭物品二次确认</summary>

关闭模板识别到物品后的二次确认。该设置可能改变误识别和漏识别的情况，具体效果取决于模板和当前画面。

默认值：关闭。

</details>

### 路线选择与分组设置

<details>
<summary><code>accountName</code>：账户名称</summary>

用于区分 `settings/`、`records/` 和 `blacklists/` 中的账户数据。多账户运行时使用不同名称。路径组一配置会将路线选择相关参数保存到该账户的配置文件中，其他路径组读取同一账户的该文件。

默认值：`默认账户`。

</details>

<details>
<summary><code>tagsForGroup2</code> 至 <code>tagsForGroup10</code>：路径组标签</summary>

这组配置项分别对应路径组二至路径组十：`tagsForGroup2`、`tagsForGroup3`、`tagsForGroup4`、`tagsForGroup5`、`tagsForGroup6`、`tagsForGroup7`、`tagsForGroup8`、`tagsForGroup9`、`tagsForGroup10` 依次对应路径组二至路径组十。每个配置项填写该路径组要匹配的标签，多个标签使用中文逗号分隔。

脚本按路径组编号从小到大的顺序匹配标签，一条路线命中多个路径组时分配到先匹配到的路径组。没有命中路径组二至路径组十标签的路线进入路径组一；路径组一没有单独的标签配置项，是默认兜底组。

</details>

<details>
<summary><code>targetEliteNum</code>：精英怪总目标</summary>

路线组合使用的精英怪总目标。脚本内部会额外预留一定数量，用于降低漏怪对目标的影响。该目标是所有选中路线的整体目标，不是每个路径组单独的目标。

默认值：`400`。

</details>

<details>
<summary><code>targetMonsterNum</code>：小怪总目标</summary>

路线组合使用的小怪总目标。脚本内部会额外预留一定数量，用于降低漏怪对目标的影响。该目标是所有选中路线的整体目标，不是每个路径组单独的目标。

默认值：`2000`。

</details>

<details>
<summary><code>priorityTags</code>：优先关键词</summary>

包含关键词的路线会被优先保留。匹配范围包括路线文件路径、路线描述中的怪物名称和路线标签。多个关键词使用中文逗号分隔。

</details>

<details>
<summary><code>excludeTags</code>：排除关键词</summary>

包含关键词的路线不参与路线选择。匹配范围包括路线文件路径、路线描述中的怪物名称和路线标签。多个关键词使用中文逗号分隔。

默认值：`蕈兽，传奇，狭窄地形`。

</details>

<details>
<summary><code>disableSelfOptimization</code>：关闭自动优化</summary>

关闭根据历史运行记录调整路线预计用时的功能。关闭后主要使用路线文件中的预计用时。

默认值：关闭。

</details>

<details>
<summary><code>efficiencyIndex</code>：摩拉与耗时权衡因数</summary>

填写 0 或更大的数字。数值越大，路线选择计算中对收益的权重越高，具体选路结果还取决于路线数据和目标数量。

默认值：`0.25`。

</details>

<details>
<summary><code>curiosityFactor</code>：好奇系数</summary>

填写 0 到 1 之间的数值。缺少运行记录的路线会按该系数调整预计用时，以增加对未知路线的尝试。调整后显示的预计用时可能与实际用时不同。

默认值：`0`。

</details>

<details>
<summary><code>ignoreRate</code>：忽略比例</summary>

填写大于等于 0 的数值后启用。普通怪物数量与精英怪物数量的比例超过该值，且路线不含受保护标签时，脚本会将该路线中的精英数量按 0 处理，使其按小怪路线参与选择。默认值 `-1` 表示关闭。

默认值：`-1`。

</details>

### 运行辅助设置

<details>
<summary><code>activeDumperMode</code>：泥头车模式</summary>

填写需要提前释放元素战技的角色编号，多个编号使用中文逗号分隔。路线文件中包含 `keypress(T)` 时，该路线不启用泥头车逻辑。角色技能效果和路线结果取决于队伍及战斗环境。

</details>

<details>
<summary><code>eatBuff</code>：路线间使用料理</summary>

填写料理名称，多个名称使用中文逗号分隔。脚本会在路线之间尝试使用料理，使用间隔为 300 秒。

</details>

<details>
<summary><code>detectRevival</code>：复活料理检测次数</summary>

填写大于 0 的整数后启用复活料理检测。使用次数按分钟统计，检测到目标后还需要经过多次确认。

默认值：`0`。

</details>

<details>
<summary><code>detectHealthBar</code>：回血料理检测次数</summary>

填写大于 0 的整数后启用血条检测和回血料理使用。使用次数按分钟统计，检测到目标后还需要经过多次确认。

默认值：`0`。

</details>

<details>
<summary><code>timeRule</code>：不运行时段</summary>

支持 `8`、`8-11`、`23:11-23:55` 等格式，多个规则使用中文逗号分隔。单独填写 `8` 时表示从 8:00 到 9:00 前；含分钟时按实际时分计算。留空表示不设置时间限制。

</details>

<details>
<summary><code>findFInterval</code>：拾取图标识别间隔</summary>

控制两次检测拾取交互图标之间的等待时间，单位为毫秒。脚本会将该值限制在可用范围内。

默认值：`100`。

</details>

<details>
<summary><code>pickupDelay</code>：拾取后延时</summary>

控制识别并按键拾取后等待下一次识别的时间，单位为毫秒。

默认值：`50`。

</details>

<details>
<summary><code>rollingDelay</code>：滚动后延时</summary>

控制拾取列表滚动后的等待时间，单位为毫秒。

默认值：`32`。

</details>

<details>
<summary><code>timeMove</code>：滚动周期</summary>

控制拾取列表上下滚动的周期，单位为毫秒。

默认值：`1000`。

</details>

<details>
<summary><code>logMonsterCount</code>：输出怪物数量日志</summary>

路线运行结束时输出脚本传入的精英和小怪数量，便于在日志分析中核对路线数据。

默认值：关闭。

</details>

<details>
<summary><code>disableAsync</code>：禁用异步队伍切换</summary>

调整队伍切换相关操作的执行方式。该设置只影响适用执行模式下的队伍切换流程。

默认值：关闭。

</details>

<details>
<summary><code>enableCoordCheck</code>：启用坐标校验</summary>

路线结束时执行坐标校验。该设置主要用于宿主没有返回路线结果的情况，也会增加路线结束阶段的处理时间。

默认值：关闭。

</details>

<details>
<summary><code>useCrystalflyCatcher</code>：晶蝶辅助传送</summary>

填写晶蝶诱捕装置坐标，格式为 `X，Y`，使用中文逗号分隔。满足当前位置、路线起点和装置距离条件时，脚本会尝试打开地图并点击装置，然后传送到路线起点。

</details>

<details>
<summary><code>targetMonsters</code>：仅指定怪物模式目标</summary>

仅在 `operationMode=启用仅指定怪物模式` 时使用。填写怪物名称，多个名称使用中文逗号分隔。脚本会在路线文件名和路线描述中进行包含匹配。

默认值：空。

</details>

## 六、脚本运行逻辑说明

<details>
<summary>启动和配置读取</summary>

脚本启动后读取当前配置。路径组一会将路线选择相关配置保存到 `settings/{accountName}.json`；其他路径组读取该账户已经保存的路线选择配置。之后脚本加载拾取模板、账户黑名单和运行记录，并根据执行模式进入对应流程。

</details>

<details>
<summary>路线选择和运行</summary>

正常模式会读取路线文件，解析预计用时、怪物数量、收益和标签，然后应用优先关键词、排除关键词、自动优化和路线组合算法。选中的路线按路径组标签分配，脚本每次只运行当前 `groupIndex` 对应的组。

仅指定怪物模式会直接在路线文件名和描述中匹配 `targetMonsters`，匹配到的路线进入路径组一。

</details>

<details>
<summary>路线结果处理</summary>

宿主返回包含布尔类型 `success` 的结果时，脚本直接使用该结果。宿主没有可用返回值且启用 `enableCoordCheck` 时，脚本读取路线起点和终点并执行坐标校验。

宿主没有返回值且关闭坐标校验时，脚本没有可靠手段确认路线是否成功，这是宿主能力限制。路线返回失败、坐标校验异常、未回到主界面或检测到重连界面时，不写入本次运行时长和路线 CD。

</details>

<details>
<summary>运行记录和数据文件</summary>

- `records/`：保存账户对应的路线 CD、有效运行时长和模板匹配拾取历史。
- `blacklists/`：保存物品黑名单。
- `settings/`：保存路径组一的路线选择配置。
- `调试结果/`：保存路线分配调试输出。
- `pathing/0-保留/`：保存用户自定义路线。
- `assets/targetItems/其他/保留/`：保存用户自定义拾取模板。

运行记录默认保留最近 7 次有效运行时长，模板拾取历史默认保留最近 20 个去重后的物品名称。失败路线不会加入有效运行时长记录。

</details>

## 七、故障排查

### 路线没有被选中

检查路线是否被 `excludeTags` 排除、是否命中路线组合目标、是否属于当前路径组，以及路线描述是否包含可解析的预计用时和怪物数量。

### 调试路线输出包含旧文件

由于 BetterGI 暂未向 JS 脚本提供删除文件的接口，执行“调试路线分配”时，`调试结果/group1` 至 `调试结果/group10` 中原有的路线文件不会被自动清除。因此，输出文件夹中可能同时存在本次结果和历史结果。

判断路线分配时应以 `调试结果/路线分配结果.txt` 中的路线清单和统计为准。建议每次重新调试前，先手动清空对应的 `group1` 至 `group10` 文件夹，再运行调试模式。

### 拾取没有生效

检查拾取模式、模板目录、物品黑名单和游戏窗口尺寸。模板匹配模式需要有效模板；BGI 原版拾取依赖宿主的 `AutoPick` 实时触发器。

### 路线记录没有更新

检查宿主是否返回 `success`，或是否开启坐标校验。路线失败、未回到主界面、坐标异常和重连状态都会跳过记录更新。

### 晶蝶辅助传送没有触发

检查坐标格式、地图坐标、路线文件中的起点坐标以及晶蝶装置是否位于识别范围内。该功能只在当前位置与装置位置满足距离条件时触发。

### 队伍切换失败

检查 `partyName` 是否对应 BetterGI 中的队伍名称。填写 `validateTeamMembers` 后，脚本还会确认指定角色是否存在；未填写时不会进行角色成员确认。
