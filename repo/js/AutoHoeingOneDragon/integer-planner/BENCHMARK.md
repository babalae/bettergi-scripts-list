# 整数规划选线：模型与实验

## 可复现输入

基线：`babalae/bettergi-scripts-list` 的 `8ad022ed88ebb29f1878b18cf5cb7b43fcf8abfa`，其中本脚本版本为 3.0.1。实验仅读取仓库内的路线描述和怪物信息，不读取任何账户、游戏记录或本地修改的路线。

使用正式 HTML 预处理与筛选入口，好奇系数为 0、忽略比例为 -1、无优先关键词，排除“蕈兽，传奇，狭窄地形”；共 555 条路线，538 条可选。稳定按路径排序后取前 128、256 条以及全部候选。估时取路线描述，收益为脚本现有的 `mora_e + mora_m`，不另计圣遗物价值。

在脚本目录运行：

```powershell
python -m pip install -r integer-planner/requirements.txt
python integer-planner/benchmark.py --repeats 9
python -m unittest discover -s integer-planner -p "test_*.py" -v
node --test integer-planner/test_integration.cjs
```

基准还需要 Node.js。输出包含输入 SHA256、环境版本、每种模式的实际数量和收益。换路线版本、机器或 Python/SciPy 版本后请重新测量。不会启动游戏、运行路线或改动用户记录。

- `07df570b72b47c09d79cd2a367a329ffd51c199ff3ce25aba63775a58f9623af`

538 条输入下，默认启发式选出 405 精英 / 2026 小怪，静态估算为 8.8589 摩拉/秒；整数规划选出 400 精英 / 2000 小怪，估算为 9.2764 摩拉/秒，最后的比值上界与结果在 `1e-7` 内一致。**两者目标函数、数量约束和漏怪余量不同，这不是同一数学问题的对打，也不是实跑收益提升证明。** 默认启发式更快；可选求解器增加的是明确约束和可检查的最优性状态。表中整数规划时间包含 Python 内的建模与求解，不含 HTTP、JSON 传输或旧算法回退准备时间；冷进程时间另外包含解释器、导入和初始化，常驻服务不需要逐次支付这些成本。

不可行例子的 256 条路线合计仅 612 小怪，无法满足 800 下限；整数规划报告无解，集成入口按约定回退并告警，不把近似数量当成可行解。

## 数学口径与边界

每条可选路线对应 `x_i ∈ {0,1}`，优化：

```text
max  Σ(mora_i * x_i) / Σ(seconds_i * x_i)
s.t. Σ(actual_elites_i * x_i) <= eliteLimit
     Σ(normal_monsters_i * x_i) >= normalTarget
     Σx_i >= 1
     x_i = 1 for required routes
```

路线必须有正的有限耗时；无效数据直接回退。每次 Dinkelbach 迭代以当前比值 q 求解 `min Σ((q * seconds_i - mora_i) * x_i)`。使用 [SciPy `milp` 的 HiGHS 接口](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.milp.html)，不是枚举全部 `2^n` 个组合，也不是把连续解四舍五入。

只有整数子问题正常结束，且通过整数、数量、必选约束验证后，才计算比值界限。若子问题的对偶下界为 L，非空组合耗时至少为 `min(seconds_i)`，则比值上界为 `q + max(0, -L) / min(seconds_i)`。上界与实际解相差不超过 `1e-7` 才返回 `optimal`；遇到时间限制、未取得有效界限或迭代未收敛返回 `incomplete`。这是浮点求解器容差下的模型最优性，不是精确算术证明。

JS 接收端还独立检查请求编号、返回状态、路线编号去重与范围、数量与必选约束、重新计算的收益/耗时/比值和上界一致性，只有全部通过才替换选中集合。服务只返回编号，不返回可执行代码或文件路径。

## 验证覆盖

- 固定种子 64 组、每组 9 条路线，与全部 `2^9` 组合穷举对照，覆盖可行/无解、必选、零精英额度、零收益和整条路线交换。
- 超时/未完成、重复或越界编号、过期请求、无效汇总、错误上界、断连/缺权限和迟到响应；失败保留原选中集合。
- 默认关闭及字符串 `"false"` 不请求网络；配置保存、跨路径组读取、旧账户默认关闭、HTML 未保存的预览值与正式调用使用同一入口。
- 本地额外将 100 组随机输入分别送入基线与新版本，默认模式的路线、顺序和标签完全一致。
- 使用与 BetterGI 相同的 ClearScript V8 7.4.5 及生产 `Http.cs`，在隔离应用上下文中通过真实回环服务验证一次成功调用和拒绝 HTTP 权限；没有进行游戏内或完整 BetterGI UI 测试。
